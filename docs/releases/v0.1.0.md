# vscode-hpc v0.1.0

First packaged release of vscode-hpc: reserve a Slurm compute node and open a
remote folder there with VS Code Remote-SSH.

## Features

- `vscode-hpc open` requests an allocation, waits for a running node, and opens
  the requested folder. Command-line options override the configured Slurm defaults.
- `vscode-hpc cancel` lists your matching jobs, cancels a selected job or all
  matching jobs, and supports a dry-run preview.
- Handles pending jobs with no assigned node and filters SSH startup chatter
  when identifying cancellable jobs.
- Provides a Python CLI and a Conda package with Python and OpenSSH dependencies.
  The source distribution, wheel, Conda package, and checksum manifest accompany
  this release on GitHub.

## Install and requirements

```bash
conda create -n vscode-hpc --override-channels -c micknudsen -c conda-forge vscode-hpc=0.1.0
conda activate vscode-hpc
```

Requires Linux or macOS, Python 3.9 or newer, local VS Code with Remote-SSH and
the `code` command, and a Slurm cluster that permits SSH to allocated compute
nodes. Configure the SSH route and `VSCODE_HPC_*` defaults as described in the README.

When upgrading from the standalone Bash script, remove or rename the old copy
and check `command -v vscode-hpc` so it does not shadow the installed package.

## Validation and limits

The 40-test suite passed against installed packages in CI on Linux and macOS,
including Python 3.9 and 3.14 and fresh Conda installations.

A functional smoke test from macOS against a Slurm cluster on 2026-11-21 passed allocation startup,
the expected compute-node terminal and working folder, dry-run selection,
cancellation, final queue removal, and observed remote-terminal shutdown.
The tested candidate was source `6cb28d43690129bd2f290a84a1cffcd5342dca09`;
release preparation changes documentation only.

CPU/memory-limit enforcement and Slurm cgroup adoption were not demonstrated.
Cleanup of every VS Code background process and editor file saving were not
verified. Other clusters require their own qualification.

Interrupting startup does not cancel the submitted allocation. Cancel the job
explicitly when finished or after a failed launch.
